# 股票分析 · 暗盘资金全景表

> **在线访问**：https://lashengcheng.github.io/stock-dark-funds/
>
> 由 GitHub Actions 自动抓取并发布，收盘后铺了 **6 个冗余时点**
> （北京时间 15:35 / 16:10 / 16:50 / 17:30 / 18:20 / 19:40），
> 任意一个成功即发布，其余时点检测到"今天已发布"会立刻空转退出。
>
> 为什么不用单个 cron：GitHub 官方文档说明定时任务在**整点高负载时可能被直接丢弃且不补跑**，
> 实测 `0 2,4,6,8` 一整天 0 次触发。故全部避开整点并做多重冗余。
>
> 运行健康度见根目录 `status.json`；若到 19:40 仍无当天数据，会自动开 issue 告警。
> 页面右下角有「数据日期 / 发布时刻」角标，可直接判断新鲜度。

## 项目说明

对 `股票代码.txt` 中的全部股票（约 3000 只）批量抓取**暗盘/明盘资金**数据，
生成与单股页面（`玄学24节气暗盘资金.html`）同源的汇总表格（CSV + 可交互 HTML）。

## 文件结构

| 路径 | 说明 |
| ------ | ------ |
| `股票代码.txt` | 输入：6 位股票代码，每行一个 |

| `scripts/fetch_all.js` | 主脚本：当日或指定日期快照（CSV + HTML + JSON 归档） |
| `scripts/backfill.js` | 补录：回看 N 个工作日，重建缺失日期的归档 |
| `scripts/daily_job.js` | 计划任务每日入口：当日快照 + 补漏，日志写 `out/logs/` |

| `out/cache/` | 暗盘日数据缓存（按 市场×交易日），重跑时跳过已完成的；`ssbk_all.json` 行业/概念缓存 |
| `out/logs/` | 运行日志：`job_日期.log`（每日任务；调度器与手动运行都写这里） |

## 使用方法

```bash
# 全量运行（3000 只 × 最近 30 个交易日，约 5 分钟）
node scripts/fetch_all.js

# 常用参数
node scripts/fetch_all.js --limit 50   # 只跑前 50 只（快速验证）
node scripts/fetch_all.js --days 5     # 只统计最近 5 个交易日
node scripts/fetch_all.js --refresh    # 忽略缓存全部重拉
node scripts/fetch_all.js --date 20261013  # 生成历史日期快照（K线行情；已有归档会跳过）
```

完成后打开 `out/暗盘资金全景表_*.html`（支持点击表头排序、筛选框、结论过滤），
或用 Excel 打开同名 CSV。

## 每日自动服务（本地）

已注册 Windows 计划任务 **`StockDarkDaily`**（每日 **17:00**，当前用户登录时运行）：

> 本机安装位置：`C:\Users\sheng\股票分析`。`register_task.ps1` 的运行目录由脚本自身位置推导
> （`Split-Path -Parent $PSScriptRoot`），项目可整体移动，移动后重跑一次注册脚本即可；
> 任务直接调用 `node.exe`（不经 cmd.exe 包装），避免中文安装路径在 shell 代码页下变成乱码。
> 该 .ps1 刻意保持纯 ASCII——Windows PowerShell 5.1 按 ANSI 代码页读取脚本，非 ASCII 字面量会被写坏。

```powershell
# 注册/更新任务（改运行时间等后重跑一次即可）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\register_task.ps1

# 查看任务 / 手动立即运行 / 删除
schtasks /query /tn StockDarkDaily
schtasks /run /tn StockDarkDaily
schtasks /delete /tn StockDarkDaily
```

每日任务（`scripts/daily_job.js`）做两件事，日志在 `out/logs/job_日期.log`：

1. **当日快照**：已过 15:30 才跑 `fetch_all`（收盘后暗盘/行情数据才稳定；未到点自动跳过，
   定时 17:00 或下次开机补跑——`StartWhenAvailable` 已开启，错过 17:00 会在下次开机时补）。
2. **补漏**：跑 `backfill --lookback 30`，回看最近 30 个工作日，把没有
   `out/history/日期.json` 的交易日重建出来（电脑没开机/任务失败漏掉的天数）。

补录原理：暗盘历史接口永久可查（照常抓），行情用腾讯**日K线**取"补录日收盘价"，
流通市值按 `今日市值 × 历史收盘 / 今日价` 近似；评分公式与当日实时路径完全同一份代码
（`lib/snapshot.js`）。休市日（暗盘当日无数据）自动记入 `out/history/_nontrading.json` 不再重试。

## 历史归档 JSON（给将来的统计服务）

每天一份 `out/history/YYYY-MM-DD.json`，**数值型原始字段**，可直接用于
"预测 vs 次日实际表现"的准确性统计（次日表现可用 K 线接口自行回查）：

```jsonc
{
  "date": "2026-10-14",            // 快照日（预测针对的交易日）
  "generatedAt": "2026-10-14T17:00:01.000Z",
  "source": "live",                // live=当日实时生成 | backfill=事后补录
  "meta": {
    "codes": 3000, "dayWindow": "2026-09-02 ~ 2026-10-14（…）",
    "validDays": { "sz": 30, "sh": 30, "bj": 30 },
    "quoteSource": "live",         // live=腾讯实时 | kline=日K线收盘（补录）
    "hasBoardZdf": false,          // false=行业热度项按中性 5 分计（当日板块涨跌未取到）
    "marketOpen": true,            // false=休市日（暗盘数据是上一交易日回声、行情无当日K线，统计时应剔除）
    "stat": { "total": 3000, "pick": 64, "pickAll": 354, "avgAi": 48, "avgVal": 54 }
  },
  "stocks": [{
    "code": "000601", "name": "韶能股份",
    "close": 6.82, "pct": 10.01,       // 快照日收盘价 / 涨跌幅%
    "rank": 69,                         // 当日该市场暗盘总榜排名
    "an": 70756800, "ming": 338000000, "zong": 408756800,   // 当日 暗/明/总净流入(元)
    "an30": 134000000, "ming30": 235000000, "zong30": 369000000, // 窗口累计(元)
    "hitDays": 30, "totalDays": 30,
    "floatMv": 71.88,                   // 流通市值(亿)；补录日为近似值
    "industry": "公用事业", "concepts": "…",
    "aiScore": 93, "strongLine": "大牛线上",
    "fundSignal": "强势流入", "comboAdvice": "积极买入",
    "value": 97, "conclusion": "入选（重点关注）"
  }]
}
```

注意：历史日期的归档一旦存在就不会被覆盖（防止补录数据冲掉当日实时归档）；
要重建某天，删除对应 JSON 后重跑 `node scripts/backfill.js`。

## 数据来源（与原 HTML 页面一致）

| 数据 | 接口 |
| ------ | ------ |
| 实时行情/名称/流通市值 | 腾讯 `qt.gtimg.cn`（GBK，批量 50 只/请求） |
| 暗盘/明盘资金 | 东方财富 `quotederivates.eastmoney.com/datacenter/darktrade`（每页100，按市场分页翻完） |
| 行业/概念 | 东方财富 F10 `emweb.securities.eastmoney.com CoreConception`（ssbk 所属板块；**与旧表格式同源**，独立域名不受 push2 限流影响，带增量缓存 `out/cache/ssbk_all.json`） |
| 行业板块涨跌幅 | 东方财富 clist（板块列表，用于评分中的行业热度项；限流时该项按中性 5 分计） |
| 历史日K线(不复权) | 腾讯 `web.ifzq.gtimg.cn/appstock/app/kline/kline`（补录历史日期的收盘/涨跌幅；格式 `[日期,开,收,高,低,量]`，已与实时行情收盘价交叉验证一致） |

## 表格列与评分公式

列与 `records_002131_screen.csv` 一致（22 列）。

- **AI评分**（0~100，与原页面相同）：涨跌(45) + 今日暗盘+明盘总资金(35) + 行业热度(10) + 流通盘(10)
- **强弱线**：≥60 大牛线上 / ≥40 小牛整理 / <40 熊股震荡
- **资金面信号 / 综合建议**：按今日总净流入 ±500 万分档（强势流入→积极买入 … 大幅流出→建议减仓）
- **投资价值评分**（本工具新增定义）：0.45×AI评分 + 0.25×30日资金分(±2亿→0~100) + 0.15×命中分 + 0.15×趋势分
- **入选结论**：≥80 入选（重点关注） / ≥65 入选 / ≥50 观察 / <50 不入选
- **命中天数**：窗口内该股出现在暗盘榜单（暗/明资金非全 0）的天数
- **真实暗盘排名**：该股在当日其市场暗盘总榜中的名次

## 经验总结（踩坑与技术要点）

> 本章是整个开发过程沉淀的经验，供拿到本项目的人少走弯路，可独立阅读。

### 接口选型与可靠性

| 结论 | 说明 |
| ------ | ------ |
| 暗盘资金历史**永久可查** | `quotederivates` darktrade 传任意历史 date 都返回当日全市场榜单（约 5300+ 只/市场），这是"漏跑可补"的基础；分页 100 只/页，按市场分查（0深/1沪/2北） |
| push2.eastmoney.com 会长时间限流 | clist / stock/get 曾被 IP 限流 2 小时以上（socket hang up）。**核心链路不要依赖它**；本项目只把 clist 的行业板块涨跌作为尽力而为项，失败按中性 5 分计 |
| emweb（F10）是独立限流域名 | 行业/概念走 `PC_HSF10/CoreConception` 的 ssbk 板块列表，稳定；其前 4 个板块名拼接恰好就是旧表"概念"列的格式（同源验证过） |
| 腾讯行情字段必须交叉验证 | `qt.gtimg.cn` 返回 GBK（Node 用 `TextDecoder('gbk')` 解）；`arr[44]`=流通市值、`arr[45]`=总市值——曾误用 `arr[43]`（其实是振幅），靠与东财 f116/f117 逐股对照才纠正。50 只/请求批量很稳定 |
| 日K线可补历史行情 | `web.ifzq.gtimg.cn` kline（不复权）每行 `[日期,开,收,高,低,量]`；先把"当日实时收盘价"与"K 线当日收盘"交叉验证一致后，才放心用作补录行情源 |

### 数据特征（容易想当然的地方）

- **暗盘接口对休市日会"回声"上一交易日数据**：2026 国庆周（10-01～10-07）每天都查得到榜单，但内容与 09-30 完全相同；识别特征是当日全市场涨跌为 0。归档用 `meta.marketOpen=false` 标记，统计时应剔除这几天。30 日累计窗口沿用原工具口径**包含**这些回声日（所有归档口径一致、跨日可比），只影响资金累计的绝对值，不影响预测统计。
- **周末查询返回空榜单**，而节假日（国庆）却回声数据——不能只按"有没有数据"判断交易日。
- **停牌股当日无 K 线**：取之前最近一个收盘价、涨跌记 0。
- **15:30 之前当日暗盘/行情未定型**：所以运行时间定 17:00，且代码里再设 afterClose() 保护，未到点自动回退上一交易日快照。

### 踩过并修掉的坑（按严重程度）

1. **分页完成条件**：clist 请求 `pz=500` 会被服务端压成 100，"返回不足一页就停"会静默截断数据——必须用响应里的 `total` 判断是否翻完。
2. **缓存"提前停止"误标完整**：暗盘抓取在目标股全部命中时会提前停止翻页，这种缓存不能标记 `listComplete`，否则之后更大的目标集会错误复用部分榜单（用 `targetsCovered` 覆盖校验修复）。
3. **命中天数分母**：节假日/抓取失败的空榜单日不能计入分母，否则命中分被稀释（`validDays` 只收非空日）。
4. **Node https 响应流错误**：响应中途断开必须 `res.on('error', reject)`，否则 Promise 永远挂起。
5. **进程不退出**：无界后台重试循环会让 Node 挂起——重试要有界（固定次数+退避），收尾显式 `process.exit(0)`。
6. **HTML 内嵌 JSON**：`JSON.stringify` 结果要 `replace(/</g,'\\u003c')`，防止 `</script>` 提前闭合标签。
7. **Windows bash 内联 `node -e`**：多层引号极易出错，稍复杂的探针一律写成独立 .js 文件再运行。

### 架构决策（为什么这样做）

- **全市场榜单整日落盘缓存**（约 54 页/市场/日）：抓一次永久复用，30 日 × 3000 只的累计计算从冷跑约 10 分钟降到缓存命中秒级。
- **当日与补录共用 `snapshot.js`**：评分公式只有一份实现，历史归档与实时表口径必然一致（重构后用统计指标对比验证：入选 64/354 不变，无漂移）。
- **归档不可变**：某日 `out/history/日期.json` 已存在就跳过，防止事后补录（缺当日板块热度数据）覆盖实时生成的归档；要重建就删掉该文件再跑。
- **JSON 存原始数值（元）**：亿/万格式化留给展示层，统计服务拿到的是可直接计算的数。
- **补录的流通市值是近似值**：`今日市值 × 历史收盘 / 今日价`（股本不变假设），只影响 10 分的流通盘分桶，精度足够。

### 验证方法论

每个接口先写 probe 单独验证返回格式 → 字段含义用第二数据源交叉验证 → 小批量（40 只）跑通 → 全量 → 重构/改动后对比统计指标确认无漂移。补录数据抽样与 K 线真实收盘核对（如 000712：10-12 收 9.78 / -2.20%，10-13 收 9.83 / +0.51%，逐位一致）。
